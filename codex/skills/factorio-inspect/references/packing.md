# Compact layouts and packing

Read this when the user asks to condense a factory. Reducing its outer width is only one measure: long feeder columns and a full-height global bus can leave most of the area empty. Use the user's screenshot or nearby factory as a density reference. Consider footprint, unused interior area and connection lengths together; a maximum height is available packing space, not a requirement to stretch every machine group over it.

For a nontrivial layout, OR-Tools CP-SAT can pack rectangular production groups using integer tile coordinates, `add_no_overlap_2d`, bounded height and a width objective. Use an isolated Python environment and retain its package versions. The local tested environment is `/Users/kp/gh/factorio-artifacts/layout-tools/.venv` (OR-Tools 9.15.6755). `check_packing.py` verifies a small optimal packing; the dense Yellow artifact's `packing.py` tests real bank sizes including access space. These are local conveniences, not required installations for every task.

Model complete working groups: machines, their input/output arms, lane mixers, output collection, fluid ports, pole access and routing space. Allow groups above/below each other and short groups to share vertical space. Preserve actual recipe and throughput calculations when resizing groups. Minimize width first, then connection lengths or congestion where useful. A solver result is optimal only for the encoded constraints; report a feasible incumbent and its bound honestly if the solve times out.

Packing does not solve transport. Route belts and pipes on the placed tile grid, accounting for underground range, facing, existing pairs, ports and different fluids. Reject a layout when its connections cannot fit; revise its templates or add routing constraints rather than treating the rectangle arrangement as a valid factory.

Reserve future connection ports before routing another network. Dense buses need explicit tap hardware and bypasses around neighboring rows. A belt branch must have a real turning/approach tile before an underground inlet; assert that every surface neighbor feeding an inlet points in the inlet’s direction, then verify flow in the engine; side-loading underground entrances can discard a lane. Shared belts need deliberate lane mixing, lane capacities and engine verification. Underground endpoint placement can steal an existing pair; check actual paired neighbors after loading.

Render an occupancy preview before publishing, and inspect whether the result actually addresses the user's requested density. Then apply the writing guide's clean conversion, roundtrip, throughput and delivery checks. Startup filling of belt/fluid buffers can last longer than expected; extend a diagnostic run when counters and inventories indicate filling, and distinguish warmup from sustained output. If an old line varies over that interval, use a matching unchanged-source control before attributing the difference to the edit.

## Router and engine checks learned from dense layouts

- Solve bus tap rectangles jointly with machine placement. On a one-way bus, every producer tap must be upstream of every consumer; physical supplier groups may still be north or south. Save the resolved plan so a parallel CP-SAT search does not silently change a layout during debugging. Try another feasible tap solution when routing fails; report routing success separately from solver feasibility.
- Reserve mixer approaches, output escape cells and the final collection corridor before other routes. A producer beside the bus may need its last collection belt converted into an underground inlet to cross the first occupied row.
- A direction-aware A* state can revisit the same tile with a different heading. Reject repeated surface coordinates within a path: otherwise a later inlet overwrites an earlier outlet, breaking the declared underground pair. Apply this to pipe routing too. Guard underground pairing on the same axis in both flow directions, and compare every planned pair to the engine's neighbor.
- Natural resources can share a machine's centre. Index exported entities by name plus position, or exclude resources from a position-only machinery lookup; otherwise tests report drills and pumpjacks as missing.
- A vertical belt next to a loader does not automatically branch into it. Give each high-volume loader a splitter branch and a belt facing into the loader. Choose the highest-volume ingredient explicitly rather than relying on recipe ingredient order. Check actual inserter pickup/drop points, throughput and both lanes. An inserter stack override is a limit; raising it did not increase available stack capacity in this map.
- Run headless instances serially when they share the default localhost port. Parallel preparation is fine; a second engine cannot bind the same port.

When a custom exporter already records whole-force science counters and full before/baseline/final snapshots, pass `--recipe utility-science-pack` (or the target recipe) to the runner. Sampling every crafting machine every second is unnecessary for that measurement and can dominate export time. Keep the counter-based checks on other production lines and engine connectivity checks.

For tight targets, a short delivery window can differ from production by a few batches while transport stock changes. Extend the measurement window and report both counters; do not weaken a delivery assertion to excuse an unverified shortfall.

Retained validated example: `/Users/kp/gh/factorio-artifacts/2026-10-05-yellow-dense` reduced Ribbon-AI Yellow from 335×65 to 164×65. Its published clean conversion produced 120.75 packs/minute and delivered 120.3 over twenty measured minutes after sixty minutes of warmup. The other five science counters matched the unchanged-source control exactly; all 256 intended underground pairs matched the engine. Use the archived source and resolved plan rather than rerunning a nondeterministic solve during verification.
